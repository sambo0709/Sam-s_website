Banking DSL — Domain-Specific Language Interpreter

Banking DSL is a custom language built in Python for expressing and executing common banking operations. Simple commands travel through a complete compiler-style pipeline—lexer, parser, abstract syntax tree, and interpreter—before changing account state.

Technologies Used

  • Python 3.9+
  • Lexer and tokenization
  • Recursive-descent parsing
  • Abstract syntax trees
  • EBNF grammar
  • Python unittest

Features

  • Deposit funds into an account
  • Withdraw funds with account and balance validation
  • Check balances and create new accounts
  • Load nine demonstration accounts at startup
  • Display lexer, parser, and AST output for each DSL command
  • Manage the account data through the Ledger simulator interface

Language Pipeline

User command
  → Lexer and token list
  → Parser
  → Abstract syntax tree
  → Interpreter
  → Bank account operation
  → Result

The language supports commands such as deposit, withdraw, balance, and create. Its EBNF specification defines valid statements, account identifiers, names, and numeric amounts before the interpreter executes them.

Testing

A seven-test Python unittest suite verifies deposits, withdrawals, balance lookups, account creation, and account-number formatting. The project uses only the Python standard library, so it can run without external dependencies.

What I Learned

This project made programming-language concepts concrete by connecting grammar rules to executable business operations. It strengthened my understanding of tokenization, parsing, tree-based program representation, interpretation, and specification-driven testing.
